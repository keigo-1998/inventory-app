## 管理番号のルール

- 0001 から順番に数字を増やす。
- **枝番号**: 「山」でまとめて仕入れたものは、山の中の1つずつに枝番号を付ける。
  - `0001-0` … 仕入れた山そのもの（元の管理番号）
  - `0001-1`, `0001-2`, `0001-3` … 山の中の1個目、2個目、3個目
- アプリでは「山（仕入れのまとまり）」と「その中の商品」をつなげて管理する。山を開くと中の商品の一覧と、山全体の売上・粗利が見られるようにする。

## 山の原価の割り振り（2026/11/13 決め直し）

- 山の残りは、ほとんど価値のない物（残りカス）になることが多い。そこで **山の仕入額は全部、枝番に割り振る**。
- 割り振り方は **予想売価の比率**。端数は予想売価がいちばん高い商品で調整する。
  - 例: 10,000円の山。枝番の予想売価 30,000 / 20,000 / 20,000 / 15,000 / 15,000円（合計100,000円）
    → 原価 3,000 / 2,000 / 2,000 / 1,500 / 1,500円
- **-0（山の残り）は原価0円**。残りが売れたら、その金額はまるごと利益になる。
- 枝番がまだないあいだは、仕入額はまるごと -0 に入っている（在庫の金額に入る）。
- あとから枝番を足したときは、「仕入額 − 売れた枝番の原価」を、まだ売れていない枝番（新しい枝番を含む）で割り振り直す。**売れた商品の原価は変えない**。
- 割り振り直しが起きにくいように、枝番は **山を仕分けするときに、売れそうなものを一度にまとめて登録する** のがおすすめ。
- 枝番を足すときは、1行ずつ **原価の付け方** を選ぶ（2026/11/14 決定）。
  - **割り振る**: 上の割り振り（割り振り直し）に入れる。最初の仕分けで、ちゃんと売れそうな物に使う。枝番がまだない山では、こちらがふつう。
  - **0円で出す**: 山の残りから原価0円で出す。ほかの枝番の原価は変わらない。あとで気が向いて出す安い物に使う。枝番がすでにある山では、こちらがふつう。
  - 0円で出した枝番は、あとで割り振り直しがあっても0円のまま（山の画面で「残りから0円」の印）。
- 会計上: どの付け方でも原価の合計は仕入額と同じなので、山全体の利益は変わらない（どの商品の利益に見えるかが変わるだけ）。税金の計算は freee 側。年度末の在庫の金額をこのアプリで出す場合だけ、山の残りが0円で少し低く出るので、税理士に一度伝えておく。
- 枝番の予想売価の合計が、割り振る原価より少ないときは「赤字の見込み」と知らせる。
- 一度試した「原価率（仕入額 ÷ 山全体の予想売価）で出して、残りの原価を -0 に残す」やり方は、残りがほぼ0円の価値になる実態に合わないのでやめた。
- この原価は「どの商品でいくら儲かったか」を見るための目安。税金用の原価は freee に入っている。

## 商品の詳細（利益の確認）

- 商品一覧で商品を押すと、その商品の詳細が開く。
- **売れた商品**: 粗利・粗利率と、計算の内訳（売値・設定送料・実送料・手数料・原価）。外貨は「€370 × 177.36円」のように換算も見せる。
- **まだ売れていない商品**: 予想売価で計算した「予想の粗利」。出品中の販路ごとに、手数料を引いた予想を並べる（送料は含まない）。
- **廃棄**: 損失（−原価）。**備品**: 売上・粗利に入れない。
- 山の枝番のときは、山全体の仕入額・売上・粗利も一緒に見せ、山の画面へ移れる。

## 商品を登録（表への貼り付け）

- スプレッドシートの行をコピーして貼り付けると、まとめて商品を登録できる。
- 登録画面はスプレッドシートと同じマス目の表。ドラッグで複数選択、⌘+C / ⌘+V、右下の■をドラッグして下にコピー、⌘+D、Delete でまとめて消す、が使える。
- 1行コピーして複数行を選んで貼り付けると、選んだ行すべてに同じ内容が入る。
- 1行目に見出し（管理番号、商品名など）があれば、列の順番は自由。
- 山として仕入れた場合は、山の管理番号と仕入額を入れると、枝番号（`0350-1` など）と原価（予想売価の比率で全部割り振り）を自動で入れる。
- 登録する前に確認画面を出し、管理番号の重複、商品名の入れ忘れ、数字の間違いを赤で知らせる。直すところがある間は登録できない。
- 登録の入口は1つにする。メニューの「まとめて登録」はなくし、右上の **「＋ 商品を登録」ボタン** に統合した（1行だけ入れれば1件の登録になる）。右上の「販売を記録」ボタンもそのまま残す。2026/11/12 決定。販売も入口を1つにし、メニューの「販売を記録」はなくして右上のボタンだけにした（スマホは下のメニューの「販売」）。

### スマホでの登録

スマホでは表の代わりに、1件ずつ入れる入力画面を出す（同じ「商品を登録」画面で、画面の幅で切り替わる。スマホは右下の「＋ 登録」ボタンから開く）。

- 上に仕入先と仕入日（今日が最初から入っている）。続けて登録するときは、そのまま使う。
- 種類は「単品」「山」をボタンで選ぶ。商品名に「まとめ」「◯点」などがあれば、山を自動で選ぶ。
- ジャンルは商品名から推測して自動で選び、違えばボタンを押して選び直す。
- 原価と予想売価は数字のキーボードで入れる。個数は −／＋ ボタン。
- 山のときは、わかる分だけ中身（商品名と予想売価）を入れる。原価は予想売価の比率で全部割り振った金額をその場で表示する（-0 は原価0円）。中身はあとから足してもよい。
- 管理番号は自動（前回の続き）。
- 「リストに追加して、次を入力」で下の一覧にためていき、最後に「◯件を登録する」でまとめて登録する。一覧から外すこともできる。
- 伝票CSVの取り込みは、パソコンの「商品を登録」画面で行う。

## 伝票の取り込み（CSV）

- 伝票のCSVをそのまま入れる。山と単品が混ざったままでよい。
- 文字コード（Shift-JIS / UTF-8）は自動で判定する。
- 仕入先・仕入日は伝票ごとに1回だけ入れる（CSVの「開催日」「会場」から自動で入る）。
- 原価は「小計」（単価＋税＋落札手数料＋税）。入場料などの伝票全体にかかる費用は、商品の原価に入れず経費として別に記録する。
- オークション側の「商品ID」は取り込まない（不要）。
- ジャンルはスプレッドシートのプルダウンのように一覧から選ぶ。文字を打つと絞り込める。一覧にないジャンルはオレンジで知らせ、登録すると一覧に追加する。
- 「種類」（単品 / 山）は登録画面でだけ使い、商品一覧には表示しない（管理番号の `-0` で区別できる）。
- 種類は、商品名に「まとめ」「山売り」「ロット」「〇点」などがあれば山の候補にする。マスを押すと切り替わる。
- 管理番号は前回の続きから自動で連番。単品は枝番号なし（`0352`）、山は `-0` を付ける（`0353-0`）。
- 新しいオークションの伝票は、初回だけ列を選んでもらい、その設定を覚える。CSVが出せないところはPDFや写真から読み取る（あとで追加）。
- 単品をあとから山に変える「山に変える」ボタンを用意する（`0351` → `0351-0`）。

## 山の画面と枝番の追加

- 流れ: ①伝票CSVなどで山を登録（`0353-0` の1行、仕入額はまるごと山に入る）→ ②山が届いて仕分けするときに、山の画面で枝番を追加 → ③あとで売れそうな物が見つかったら、同じ画面から足す。
- **山の画面は商品一覧から開く**。山（-0）の行に「山 ▸」（枝番があれば「山の残り ▸」）の印があり、押すと山の画面が開く。枝番の商品の詳細からも「山の画面へ」で行ける。
- 商品一覧の絞り込みに「山」ボタンを置き、山だけを一覧で出せる。上のメニューの「山の詳細」タブはなくした。
- 商品一覧では、**山（-0）の行のすぐ下に、その山の枝番を並べる**（2026/11/14）。枝番もふつうの在庫として見える。
  - 山の行は色付き（薄いオレンジ・左に濃い線・太字）、枝番は「└」で字下げして薄い色。単品の行はそのまま。
  - 絞り込み（在庫・出品中など）は枝番にもかかる。当てはまる枝番があれば、見出しとして山の行も出す。
  - 「山」ボタンでは、山の行と枝番をすべて出す。
- 山の画面: 仕入額・売上合計・粗利合計・枝番（売れた数／枝番の数）、仕入額の回収、枝番の一覧（いちばん下に -0）、枝番を追加。
- 枝番の追加: 商品名・予想売価・原価の付け方（割り振る／0円で出す）を入れる。管理番号（続きの枝番）と原価は自動。割り振り直しになる枝番は「→ 新しい原価」で見せてから登録する。登録は「元に戻す」で取り消せる。

## 販売の記録

- 売れたことはメルカリなどの通知を見て手で入力する（CSVで出せる販路はほとんどない）。
- 入れ方は2つ。
  - **1件ずつ**（スマホ向け）: 管理番号 → 売り先を選ぶ → 売値・設定送料・手数料・実送料。計算の内訳と粗利がその場で出る。
  - **まとめて入力**（パソコン向け）: 1行に1件。管理番号を入れると商品名が出る。スプレッドシートから貼り付けもできる。
- 売れた商品は **商品名か管理番号の一部で探す**。候補は在庫（在庫・出品中）だけ。ひらがな・カタカナ、全角・半角の違いは気にしなくてよい。スペースで区切ると複数の言葉で絞り込める。
- 記録すると、商品一覧の状態が自動で **「売却済み」**（廃棄・備品は「廃棄」「備品」）になり、売れた販路が緑色になる。
- **間違えたときの取り消し**:
  - 記録した直後に出るお知らせの「元に戻す」（10秒間）。まとめて入力した分は、まとめて元に戻せる。
  - 「今日記録した販売」の一覧の「取り消す」（確認してから取り消す）。
  - 取り消すと、商品は記録する前の状態（在庫・出品中）に戻る。
  - 本物のアプリでは、過去の販売も商品の画面から取り消せるようにし、取り消した記録も履歴として残す。
- 売り先のボタンに「廃棄」「備品にした」もある。廃棄は原価を損失として記録、備品は売上に入れない。
- 手数料が「毎回入力」の販路は、いつもの手数料率の目安を表示し、大きく外れたらオレンジで知らせる。
- 実送料がまだ分からないときは「送料未定」にして、**仮の送料（だいたいの金額）** を入れておく。あとで本当の送料に直す。2026/11/12 決定。
  - 1件ずつ: 実送料の横の **「未定」ボタン** を押すと、入力欄がオレンジの「仮の金額」の欄になる。もう一度押すと戻る。
  - まとめて入力: 実送料のマスの **「未定」ボタン** を押して仮の金額を入れる。「未定 800」「仮 800」と打つ・貼り付けてもよい。「確定」を押すと、その金額で確定になる。空欄は0円として扱う。
  - 未定の間は、**仮の送料で粗利を計算**して表示する（「仮」の印を付ける）。仮の金額を入れなかったときは0円で計算する。
  - あとで直す場所: 「販売を記録」の **「送料未定」タブ**（件数のバッジ付き）。各行に仮の送料と仮の粗利を表示し、本当の送料を入れて「確定」。粗利が計算し直され、一覧から消える。直後は「元に戻す」で仮の金額に戻せる。
  - ダッシュボードの上に「送料が仮のままの販売が○件あります」と出し、そこからタブに移れる。
  - 商品の詳細でも、実送料の行に「仮」の印と「本当の送料を入れる」が出る。
- 計算方法は「販路の設定」で販路ごとに決める（[profit-formulas.md](profit-formulas.md)）。

## 見た目の方針 2026/11/12 決定

- **カードをむやみに増やさない。** 関係のある数字は、今あるカードの中に小さく書き足す。
  - 例: 売上のカードに「目標 ¥1,000,000 の49%」、在庫（残原価）のカードに「出品中 316点（出品率77%）・未出品 96点」
- ダッシュボードの数字は **EC（物販）の数字** だと分かるように、見出しに「（EC）」と書く。法人売上は別に出す。
- 今月のカード: 売上（目標の達成率を小さく）、粗利、在庫（残原価・点数・出品率）、成約件数
- 「今月の日ごとの数字」のグラフ: 売上・粗利／仕入額／出品数／成約件数 をボタンで切り替える（1つのグラフに全部重ねない）。月ごとの売上と粗利のグラフはそのまま残す。
- 一度メニューを4つにして売却ログなどを足した版を作ったが、カードが増えて見にくかったので前の形に戻した。

## 商品一覧の絞り込みと状態 2026/11/12 決定

- **「在庫」は、今あるすべての在庫**（未出品＋出品中）。出品中のものも在庫に入る。
- 状態の名前は「未出品」「出品中」「売却済み」（「在庫」という状態の名前はやめた。出品中も在庫なので紛らわしいため）。
- 絞り込み: すべて／在庫／未出品／出品中／売却済み／90日以上
- 検索: 「🔍 検索」ボタン（Enterでも可）で、管理番号・商品名で絞り込む。
- 縦積在庫は、商品名の横に「残り5／8個」と小さく表示する（列やカードは増やさない）。

## まとめ買い（違う商品を同じお客様が買う） 2026/11/12 決定

- 売値は販路の画面で商品ごとに分かるので、商品ごとにそのまま入れる（自動で分けない）。
- 送料は1箱分を、**どれか1つの商品にまとめて入れる**。ほかの商品の送料は0円。
- 販売の記録では「まとめ買い」の印を付けて、どの商品に送料をまとめたか分かるようにする（画面イメージはまだ）。

## 縦積在庫（同じ商品が複数個）の一部販売 2026/11/12 決定

時計やアパレルなど小さいものが多い。数はそこまで多くなく、まとめて何個も売れることも少ない。同じ商品なら原価は同じ。

- 販売を記録するとき、縦積の商品を選ぶと「在庫 残り○個」と「個数」の欄が出る（最初は1）。
- 2個以上のときは、売値は **合計で入れる**（欄の名前が「売値（3個の合計）」になる）。
- 原価は「1個あたりの原価 × 個数」で自動計算。
- まだ残りがあれば、出品中のまま。取り下げのお知らせも出さない。
- 最後の1個が売れたら「売り切れ（売却済み）」になり、ほかの出品先の取り下げを知らせる。
- 商品の詳細に「在庫 残り○個／仕入個数」を表示する。
- 「まとめて入力」での個数の入力は、本物のアプリを作るときに足す。

## 同時出品の取り下げ 2026/11/12 決定

ふだんは1つの商品を2つの販路に出している。2回売れてしまったことは基本的にないので、シンプルにする。

- 売れたことに気づくのは、今までどおり販路からの通知やメール。人が「販売を記録」で記録する（将来はGmailの「売れました」メールから販売の下書きを自動で作る → 7）。
- 販売を記録したとき、ほかにも出品中の販路があれば「⚠ ほかに出品中：ヤフオク の出品を取り下げてください」と表示する（記録したときのお知らせと、「今日記録した販売」の一覧）。
- 商品の出品先からは、売れた販路以外を自動で外す。記録を取り消すと元に戻る。
- 「取り下げ待ち」の印や件数の管理はしない（必要になったら足す）。

## 返品・キャンセル・一部返金 2026/11/12 決定

ほぼないが、たまにある（返送用封筒を送って返品してもらう、など）。売却済みの商品の詳細にある「返品・返金があった」ボタンから記録する。

| 種類 | どんなとき | 販売の記録 | 商品 |
|---|---|---|---|
| 発送前のキャンセル | お金も送料もまだ動いていない | 消す（記録の取り消しと同じ） | 元の状態に戻る |
| 返品 | 発送した後、商品が戻ってくる | 消さずに「返品」として残す。売値は0円、**行きの送料＋返品の送料（返送用封筒など）＋戻らない手数料**を損として残す | 在庫に戻る。**同じ管理番号のまま**売り直す |
| 一部だけ返金 | 傷があったので値引き、など | 「返金額」を入れ、その分粗利が減る | 売却済みのまま |

- 戻らない手数料は、最初は販売のときの手数料を入れておく。販路が手数料を返してくれたときは0にする。
- 確定済みの月の月次レポートは書き換えない。返品・返金があった月のレポートに、マイナスの行として載せる（モールも返金した月の振込から引くことが多いため）。
- Catawikiなど海外の販路は、返品の送料が高くなりそう（まだ実例はない）。
- **販路の設定で決める**（販路ごとに違うため）: 「実送料の払い方」（販路の振込から引かれる／法人口座から払う）と「一部返金のふだんの返し方」（販路の振込から引かれる／法人口座から振り込む）。月次レポートの振込予定額とfreee取込用CSVはこの設定から計算する。一部返金は、記録するときにその都度変えられる。
- **一部返金の返し方**: 販路の振込から引かれる（メルカリなど）か、振込先を聞いて法人口座から振り込む（ヤフオクなど）かを選ぶ。販路ごとにふだんの返し方を決めておき、最初から選ばれているようにする。法人口座から振り込んだ返金は、送料と同じくfreee取込用CSVに入れない。
- **二重計上しないためのルール**: アプリの粗利（社内の儲けの計算）には返品の送料も入れる。ただし、法人口座から払った送料は、freeeでは銀行の明細から荷造運賃として登録済みなので、**freee取込用CSVと振込予定額には入れない**。freeeに渡すのは「販路が振込から差し引いた金額」だけにする。

## 月次レポート（PDF）とfreee会計 2026/11/12 決定

**目的**: freee会計に1か月分の売上を販路ごとに登録し、販路からの1か月分の振込と消し込む。そのときの根拠（証拠）として、このPDFを取引に貼って保存する。

- **流れ**:
  1. 毎月1日の朝に、前の月の分の「下書き」を自動で作る（前の月の平均TTMが確定してから）
  2. **10日までに**、仮のままの送料を本当の金額にし、販路ごとに通帳の「実際の振込額」を入れる
  3. 「確定して保存」で第1版として保存する（下書きのPDFには「下書き」と表示）
- **振込予定額（販路ごと）**: 売上高 − 販売手数料 − 振込から引かれる送料
  - 売上高 ＝ 売値（円）＋ 設定送料（円）
  - 振込から送料が引かれる販路: メルカリ・ヤフオク（販路の設定に「送料が振込から引かれる」を持たせる）
  - 原価は仕入先の請求書でfreeeに登録済みなので、振込の計算には入れない
  - 実際の振込額との差額を表示する。仮の送料を本当の金額にすると、差額が消えることが多い
- **freeeへの登録の形**（今の登録のしかたに合わせる）: 販路ごとに1つの収入取引。発生日は月末、取引先は販路。
  - 売上高（課税売上10%）/ 販売手数料（課対仕入10%・マイナス）/ 荷造運賃（課対仕入10%・マイナス）
  - 備考の例: 「メルカリ　10月売上」「メルカリ　10月販売手数料」「メルカリ　10月送料」
- **freee取込用CSV**: 販路ごと・全販路の両方を出せる。列は「発生日・取引先・勘定科目・税区分・金額・備考」。実際の列の形は、作るときにfreeeの取込画面に合わせる。将来はfreeeと直接つなぐ（→ 7）。
- **PDF**: 1つの形にまとめる（freee用と社内用に分けない）。
  - 全販路のPDF: 振込との突き合わせ表、まとめ（売上・粗利・粗利率・件数）、販路ごとのまとめ表、販路ごとの明細
  - 販路ごとのPDF: その販路だけの突き合わせと明細。freeeの各販路の取引には、その販路のPDFを貼る
- **明細の中身**: 売却日、管理番号、商品名、売値（外貨の販路は外貨と円の両方）、設定送料、実送料、手数料、原価、粗利。廃棄・備品にした商品は売上に入れない。
- **作り直し**: 確定後に数字を直したら作り直せる。作り直すと「第2版」になり、前の版も消さずに残す。
- **保存とダウンロード**: 「月次レポート」画面に月ごとに並べ、いつでも開ける・ダウンロードできる。ファイル名の例：`JOYNT_月次販売レポート_2026-10_メルカリ_第1版.pdf`
- **途中経過**: 今月の分は、途中までの数字（為替は仮のレート）で同じ形のものを見られる。
- **まだ決めること**:
  - Catawiki・JOOM（外貨の販路）の税区分と、為替による振込額のずれの処理（税理士に確認中）
  - 見るだけの人（外部の人）にもダウンロードを許すか（→ 5）、メールやLINEで自動で送るか（→ 7）

## まとめて売る（山売り・合わせ売り）

- 商品一覧で、単品・枝番・山の残り（-0）にチェックを入れて「まとめて売る」。新しい管理番号は作らない。
- **販売の記録は1件（1行）**。押すと中身の商品が見える。中身はすべて売却済みになる（-0 を入れた山は残りが0になる）。
- 例: 山1の残り（0460-0）と山3の残り（0470-0）を一緒にヤフオクで売る → 1行で記録。-0 の原価は0円なので、手数料を引いた金額がそのまま粗利。
- 粗利 ＝ 売れた金額 − 手数料 − 中身の原価の合計。
- 山ごとの成績のために、売れた金額を **予想売価の比率** で中身に分ける（-0 は残りの予想売価）。手で直せる。合計が売れた金額と合わないと記録できない。
- 枝番を選んだときに、その山の残り（-0）がまだあれば「山〇〇の残りも一緒に入れる」を出す。
- 山の残りのうち一部だけ売りたいときは、先にその分を枝番にしてから売る（-0 は「山の残り全部」）。
- 記録したあと「元に戻す」で取り消せる。ほかに出品中の販路があれば取り下げを知らせる。

## 同時出品

- 1つの商品を複数の販路に同時に出品する。

- どこかで売れたら、ほかの販路の出品を取り下げる必要があることを画面で知らせる。

## 為替レート（自動）

- 外貨（ユーロ・ドル）の売値は、手で入力しなくても自動で円に換算する。
- レートはインターネットから自動で取得して保存する。
- 基準は **売れた月の平均TTM**。
  - 月の途中は、その月の **月初のTTM** を仮のレートとして使う（画面に「仮」と表示）。
  - 月末になったら、その月の平均TTMを計算し、その月の売上をすべて自動で計算し直して確定する。
- 取得元は三菱UFJ銀行が毎日発表しているTTM（予定）。

## 全体の考え方

- 「在庫管理①」は1行に仕入れと販売の情報が一緒に入っている。アプリでは **商品（在庫）** と **販売（売上）** に分け、画面ではつなげて表示する。
- 「在庫管理①」（1点もの）と「縦積在庫管理②」（複数個）は、**商品** 1つにまとめる。個数が1なら1点もの。
