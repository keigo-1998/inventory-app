## 1. 設計・画面イメージ

### 決まったこと
- 商品（在庫）と販売（売上）を分けて管理する
- 管理番号は連番、山は `-0`、山の中は枝番（`0001-1`）
- 山の仕入額は全部、枝番に予想売価の比率で割り振る。-0（山の残り）は原価0円。枝番は山を仕分けするときに、商品一覧から開く山の画面で追加する
- 山の残りやほかの商品を合わせて売るときは、販売の記録は1件（1行）
- 伝票CSVをそのまま取り込む（山と単品を切り替え）
- 販路ごとの通貨・為替・手数料のルール（[profit-formulas.md](profit-formulas.md)）
- 販売は商品名で探して記録、記録すると売却済み、取り消しもできる
- 商品を押すと利益が見られる
- 送料が未定のときは仮の送料を入れておき、あとで確定する
- まとめ買いは売値を商品ごとに入れ、送料は1つの商品にまとめる
- 縦積在庫は個数を入れて記録（売値は合計、原価は1個あたり×個数）、残りがあれば出品中のまま
- 同時出品は、販売を記録したときにほかの出品先の取り下げを知らせる
- 状態（未出品・出品中）は出品先から自動で決まる。出品先は商品の画面で1点ずつ、商品一覧でまとめて変える
- データは消さない・戻せるようにする（毎日のバックアップ・削除はゴミ箱・変更の履歴・権限・手元への書き出し）
- 返品は記録を残して損（送料・戻らない手数料）を記録、商品は同じ番号で在庫に戻す。一部返金は返金額を入れる
- 売却ログは画面を作らず、月次レポートの「すべての販路」で見る
- 月次レポート（販路ごとのPDF）を毎月1日に下書き、10日までに振込額と合わせて確定。freeeに貼る根拠にし、freee取込用CSVも出す

### まだ決めること
- 振込額と合わないときの扱い（月のずれ・手数料の端数・為替の差。1件ごとに振込額を入れるか）※最後に決める
- 法人売上・固定費・売上目標の入力方法（→ 4）
- ダッシュボードの数字（未出品・出品率・会社としていくら残ったか）※一度作って、前の画面に戻した。見せ方を考え直す

## 2. 本物のアプリを作る（いまここ）

道具: Next.js ＋ Prisma ＋ SQLite（公開するときに PostgreSQL へ）。最初に入っていた備品管理のたたき台は外した（2026/11/14）。

- ✅ データベースの設計（商品・山・出品先・販売・販路・為替レート・変更の履歴）。「削除はゴミ箱」と「変更の履歴」も最初から入れた。見本データと確認用の画面あり
- 🔶 商品一覧・商品の詳細（✅ 絞り込み・検索・山の並び・出品先の変更・元に戻す。⬜ 山の画面・まとめて売る）
- 商品を登録（スプレッドシート風の表・伝票CSV・スマホの1件ずつ入力）

- 販路の設定
- 為替レート（ユーロ円・ドル円のTTM）の自動取得

## 3. 移行と並行運用

- スプレッドシートの「健康診断」（件数、名前の揺れ、入力漏れ）
- 在庫管理①・②の取り込み
- アプリの粗利とスプレッドシートの粗利を突き合わせ、違う行を確認
- 全件をCSV／Excelで書き出す機能、毎日スプレッドシートへ自動で写す機能
- しばらくは両方使い、問題がなければアプリに切り替える

## 4. 経営の数字

- 法人売上（請求書ごと）
- 固定費・売上目標
- 月次レポート（EC・法人の売上と粗利、固定費、営業利益、目標達成率）
- 販路ごとの月次販売レポートPDF・振込との突き合わせ・freee取込用CSV（毎月1日に下書き、10日までに確定）※画面イメージあり。2 の販売の記録ができたら先に作れる
- ダッシュボードを詰める

## 5. ログインとインターネット公開

- Googleでログイン、招待した人だけ使える
- 権限（管理者・スタッフ・見るだけ）
- クラウドに置く（アプリ: Vercel など、データ: Supabase / Neon など）
- 毎日の自動バックアップ
- 公開前に安全上の問題がないかチェック

## 6. デザインの仕上げ

- 見本を集めて方向性を決め、2〜3パターンを比べる
- 色・文字・余白・アイコン・動きを整える
